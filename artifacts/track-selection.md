## Pitch framing (what judges hear)

- **Credibility anchor: impact-based forecasting.** This is WMO's term and IMD has adopted the approach. Slogan: *"Forecasts tell you what the weather will **be**. We tell you what it will **do**."*
- **Product loop: Predict → Prioritise → Prepare → Prove.**
  - **Predict:** hazard at every asset.
  - **Prioritise:** ranked, explained assets at risk.
  - **Prepare:** typed actions and a local-language advisory, dispatched only after an officer approves.
  - **Prove:** post-event satellite verification plus the historical backtest. This is the differentiator.
- **Opening line:** *"A post-mortem, written 48 hours before the storm."* Alternative: *"Triage for a coastline."*
- **Never use "EDA" in anything judges see.** The acronym reads as Exploratory Data Analysis, and "Exception → Drilldown → Action" is internal client framing, not a standard term. It stays below only as the internal design checklist.

## Internal design checklist (Exception → Drilldown → Action)

Every track has this shape, and it is the direct antidote to "dashboard + chatbot" entries. Principles carried over from prior agentic-reporting design work:

1. **Deterministic detection, LLM explanation.** Code decides breach/recovery (thresholds, wind field, exposure score); the model explains, ranks and drafts — it never submits authoritative pass/fail values.
2. **Stable subject keys** (e.g. `exposure:fani-2019:substation:osm-123`) so a scheduled re-run updates rather than duplicates an exception, and a handled action does not reappear (no alert fatigue).
3. **Drilldown per exception** — the evidence charts/tiles behind the flag, saved as the exact request that produced them (never re-aggregated).
4. **Decision-context page** — sources, freshness, checks passed/failed, confidence breakdown, lineage, assumptions.
5. **Typed actions with a mandatory human press** — ASSIGN, DRAFT_MESSAGE (nothing sent until approved), SNOOZE, DISMISS with cool-off, OPEN_LINK; the agent recommends, never presses.
6. **"All clear" is a first-class state**, not an empty page.
7. **Forecasts come from the data layer** (official bulletins, NWP, WeatherNext), never generated by the LLM.
8. **Append-only evidence and run log** — which data, prompt/model version and confidence produced each recommendation.

## Why Track 5

- It is the only track that names Google's own stack (**Earth Engine + Gemini 3.7 Flash**) — judges from Google reward seeing it used seriously.
- The CV background is the differentiator: most entries will draw a buffer and red markers; this one extracts SAR flood extent, optical damage and night-light blackouts.
- **Backtesting is the killer feature**: flag at-risk assets from pre-landfall information, then show post-landfall satellite evidence of what actually happened — direct proof for the 25 % technical-execution criterion.
- Parametric-insurance triggers are named in the challenge text and almost nobody will build them.
- Runner-up: Track 2 (demo day in late October coincides with stubble-burning/smog season; live data would be real).

## Constraints that apply regardless

- Google AI must perform a consequential task; Google Cloud hosts the deployment (development may use Claude Code / Codex).
- Human approval before any advisory dispatch; label scenario/replay mode clearly; declare every proxy layer.
- No personal data; public/licensed data with citations; synthetic data labelled.
